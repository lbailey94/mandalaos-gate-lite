## 3. Known deviations / gotchas (also contract §14)

- `systemd-run --pipe` captures stdout; on systemd 255 a signal-killed payload
  reports `rc=0/success` through `--pipe` — operator kills are proven by the
  kill request + termination receipt + latency.
- MCP HTTP handler sets `TCP_NODELAY` (benchmark: keep-alive ping 41 ms →
  0.42 ms). Operator kill sends SIGTERM then escalates to SIGKILL after a 1 s
  grace (benchmark: p95 5.1 s → 1.1 s; SIGTERM alone can be missed during
  sandbox startup, SIGKILL always lands).
- Desktop OOM notifications: bench OOM drills (and the G2 acceptance tests)
  kill payloads via memcg OOM, which makes `gsd-housekeeping` show
  "Application Stopped / memory nearly full" popups. The bench drill is now
  opt-in (`--oom`); there is no gsettings toggle for the notification.
- `CPUQuota` throttles; memory and wall are the kill dimensions.
- HTTP transport is loopback-only, no TLS; `--token` optional.
- **Workspace `rw: true` requires the updated host wrapper.** If the wrapper
  is replaced/reinstalled from the sovereign module, mirror this change
  (additive: envelope `rw` → `--bind` instead of `--ro-bind`).
- Redaction rewrites signatures: `disclose redact` needs the issuer key and
  re-signs the chain tail from the first modified receipt (issuance-time act).
- `~/.local/bin/wm` still not reachable inside the sandbox (no bind for it);
  a `ro_binds` envelope field would generalize this when wanted.

## 8. 2026-09-22 — S2b pass-binding additions (opencode)

Cross-system pass binding with WhiteMagic (ecosystem S2, scope:
`WHITEMAGIC/planning/private/RECEIPTS_S2_SCOPE_2026-09-22.md` §5):

- **Claims additions:** `pass_id`, `slot_id`, `mandate_ref` (and
  `principal_id` when supplied) now travel in the pass token claims, so a
  relying party can join its own receipts to the pass offline.
- **`session.pass.created` commits the token:** body gains
  `pass_token_id = sha256(token)` (spec §4.1 field). WM records the same
  value in its governed-dispatch receipts — it is the cross-system join key.
- **New tool `mandala.pass.verify`:** `{token} -> {valid, claims, pass record,
  jti_seen, gate_id, policy_version}` — registry state without a new IPC
  surface beyond MCP.
- **`mandala.exec` enforcement:** when a token is supplied it must bind to the
  executed slot (`claims.slot_id == args.slot`, else `token_slot_mismatch`)
  and is single-use per gate process (`pass_replayed`); the jti is recorded
  only after every check passes, so a rejected attempt cannot burn a token.
  Token remains optional — v0 behavior is unchanged when omitted.
- **Tests:** 64 green (`tests/test_orchestrator.py` pass-claims/receipt-binding

## 10. 2026-09-24 — authorization contract (opencode)

The §9 known gap is closed. Three enforceable rules, implemented and tested:

1. **Tenant membership at issuance** — `pass_()` rejects agents not in
   `Tenant.agents` (`PassError agent_not_registered`; CLI rc 2, MCP
   structured error). Previously any agent DID was accepted for a known
   tenant.
2. **Token required at execution** — `exec_()` requires a pass token that
   verifies against this gate, is unexpired, and binds to the slot's pass and
   the pass's agent (plus the caller-supplied `agent` when given). CLI:
   `mandala-ctl exec --token` is now required. MCP: `mandala.exec` `token` is
   required (schema `required` updated).
3. **Durable replay** — jti consumption moved to the SQLite registry
   (`consumed_tokens`, atomic `INSERT OR IGNORE`): rejected across restarts
   and under concurrent requests (8-way race: exactly one winner). Attempts
   rejected before any work starts (state checks, CAS loss, emitter down,
   runner pre-start failure) release the token, so failed attempts do not
   burn passes; `idempotency_key` replay still returns the cached result
   without re-consuming.

Cross-tenant slot access unchanged (`_authorized_slot`). Suite 71 → 79
(orchestrator: membership, token required, subject mismatch, restart replay,
8-way concurrency; registry: atomic consume/durable/release; MCP:
token_required + agent_not_registered; CLI: --token required). Dogfood and
bench updated: one pass per exec; bench loops draw from a pre-issued pass
buffer.

## 11. 2026-09-24 — idempotency cache authorization fix (opencode)

Follow-up to board #203/#204 (external review): `pass_()` and `exec_()`
returned cached idempotency results before authorization. Fixed:

- `pass_()`: tenant lookup, `Tenant.agents` membership, and slot-class
  validation run before the cache; cache keys are tenant+agent scoped
  (`pass:<tenant>:<agent>:<key>`); a key reused with different request
  parameters is rejected (`ValueError: idempotency key reused with a
  different request`).
- `exec_()`: `_authorized_slot` + token verification (signature, expiry,
  subject, slot/pass binding, pass record) run before the cache; keys are
  tenant+slot scoped (`exec:<tenant>:<slot>:<key>`); the payload must match
  the cached request. `_verify_exec_token` (side-effect free) and
  `_consume_exec_jti` are now separate, so cached replays verify without
  re-consuming and rejected attempts never burn a token.
- Legacy cache entries under the old global keys (`pass:<key>`,
  `exec:<key>`) are simply unreachable; new keys are scoped.
- Behavior note: state rejections (frozen/terminated/expired) now also
  require a valid token — auth precedes the state checks, so slot state
  cannot be probed without one.

Regression tests: cached replay without token (`token_required`), cached
replay cross-tenant (denied), key scoping across tenants/agents, changed
payload/request on an existing key (rejected); legitimate replay still
returns the identical result. Suite 79 → 86.
